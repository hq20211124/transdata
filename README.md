# TransData —— 内网文件互传工具

两台电脑（或电脑与手机）在同一局域网内互传文件：一端运行 GUI 程序，
另一端用浏览器访问 `http://<IP>:9999` 即可上传/下载，全程不经过互联网。

## 使用

把 `transdata-rs/target/release/transdata.exe` 拷到目标电脑，双击运行：

1. 窗口显示服务器状态、访问地址（IP:端口）、手机扫码二维码、**8 位配对码**、
   当前传输目录（默认 `<exe所在目录>\uploads`，可点「更改」切换）。
   本机地址变了（换了手机热点、DHCP 重新分配）时二维码**自己重画**，不用手动刷新；
   「刷新二维码」那个按钮是做另一件事的——换一张新配对码（旧码立刻失效）
2. 另一端浏览器打开该地址：
   - **连接**：手机扫码即自动配对；不方便扫码时，在电脑上看到的「配对码」
     （8 位数字，每次启动变化）手动输入即可。**未配对的设备无法访问任何文件**
   - **上传**：点「选择文件」传散文件（可多选），或点「选择文件夹」——目录结构原样保留；
     大文件夹会自动分批传输、失败自动重试，完成后自动逐条校验（path+大小），
     显示"共 N 个文件，校验全部通过"。已传好的文件自动跳过（断点续传效果）。
     手机浏览器不支持选文件夹（Web 限制，非本程序问题）：点「选择文件夹」会退化成
     普通多选并给出提示；文件很多时建议先在手机里把文件夹压缩成 zip 再传
   - **下载**：按目录树展示（文件夹带 ▸ 可展开），**只有目录才有「打包」**——
     把整个文件夹压成 zip 下载；文件行有「下载」「重命名」「删除」。
     「下载」支持断点续传（`Range` / 206）：手机热点抖一下不用从头再下。
     链接自带签名凭证，所以交给系统下载器的浏览器（Via、X 浏览器）也能下——
     它们那条连接不带会话 Cookie。
     重命名框里可以直接带子目录（例如输入 `归档/a.txt`）——改名和移动是同一个操作，
     目标已存在时会被拒绝，绝不覆盖。
     底部「全部打包下载」= 整个传输目录打成一个包。
     打包是**边压边传**的：点完马上开始下载，浏览器里能看到进度；
     中途关掉页面/关掉桌面端，服务端会立刻停手，不会白忙一场
   - **快捷文本**：两端同步的便签（4 MB 以内，网页和 WebSocket 两条路都一样限）；
     右上角按钮可展开成全屏编辑，复制/发送的提示在便签里显示 10 秒

## 界面

- **电脑端是「管理端」**（v1.3）：一屏三栏，窗口 1200×760，不用切页签、不用翻视图
  - **左｜目录**：传输目录的文件树（文件夹 ▸ 可展开、子项缩进、文件夹排在文件前），
    列头 `名称 / 大小 / 修改时间`，行高 30px；工具栏是路径框 + 刷新 + 打开目录 + 更改；
    行内 ✏ 改名、🗑 删除；底部状态栏 `已选中：…` + `N 个文件夹 · M 个文件 · 总大小`
  - **中｜连接 + 设备**：二维码 + 配对码 + 地址 + 复制地址，一行 HTTPS 开关（开了多一行证书指纹）；
    下面是设备表 `设备 / 空闲 / 删除/修改`，一行一台（同一 IP 的多个标签页算一台），
    每行有授权开关和「断开」
  - **右｜设备操作详情**：点哪台看哪台——它自己的上传 / 下载 / 删除 / 改名记录
    （操作 · 文件 / 大小 / 时间），一屏约 20 条
  - 窗口窄于 1000px 时右两栏收起，标题栏出现 `设备 (n)` 抽屉按钮（三栏放不下，不做横向滚动）
- **电脑端其余**：自绘标题栏（图标 + 名称 + 版本号 + `运行中 · 端口 · N 台设备` +
  主题（月亮/太阳）、设置（齿轮）、最小化/最大化/关闭），窗口四角圆角；
  **可以拖边缘改大小**（最小 640×470）；Esc 一次只退一层（改名 → 删除确认 → 设置）
- **单实例**：双击第二次只会弹一句「已经在运行了」，不会再开出一个抢端口、
  还会把前一个实例正在上传的临时文件当垃圾删掉的窗口
- **手机端**：单屏 app 布局——顶部状态条、**上传/下载 Tab 切换**、底部**吸底发送框**
  （发消息不用再滑到底）；文件列表默认只显示 8 条、展开后在列表内部滚动，
  页面永远不会被几十个文件撑长

## 管理端目录（电脑端左边那一栏）

这是**传输目录本身**（不是"上传/下载列表"）——它就是这台机器上的那个文件夹，
只是换了个更顺手的界面来管理。

- 删 / 改名**不是**直接动文件系统，而是走和网页端同一套操作（`src/ops.rs`）：
  同一把锁、撞名绝不覆盖、越界路径拒绝、删除后配额立即归还、活动日志记一笔「本机」
  - 这样管理端和别的设备**排在同一条队**上：不会删掉别人正在写的目标，
    也不会两边改名互相覆盖
- **诚实边界**：只保证"通过本程序的操作"之间原子。你拿资源管理器直接动同一个目录，
  程序管不了（Windows 权限模型决定的）。工具栏保留「打开目录」，
  但默认建议在这个列表里操作
- **改名**：点行内铅笔 → 名字原地变成输入框，**只选中主文件名**（不含扩展名），
  `Enter` 提交、`Esc` 取消；文件夹也能改名。失败在状态栏红字给原因（撞名 / 正被占用 / 名字不合法）
- **删除**：点垃圾桶 → 居中确认窗。文件写「不可撤销，配额立即归还」，
  文件夹写「文件夹和里面的 N 个项目会一起删除」
- 列表由后台线程读（3 秒节流，最小化不刷），所以大目录不会把界面卡住；
  渲染上限 500 行，超出会写明「仅渲染前 500 行」

## 设备授权（删除 / 修改）

三个词先说清楚，界面上就按这个写：

| 词 | 含义 |
|---|---|
| **删除 / 修改** | 授权开关。管 `DELETE /delete/*` 和 `POST /rename`（改名属于"修改"）。**默认开** |
| **传输** | 上传 + 下载 + 打包下载。**永远可用**，不受授权开关影响 |
| **断开** | 踢掉该设备的会话，对方要重新扫码/输码。和授权是两件独立的事 |

- **关授权 ≠ 断开**：关掉之后对方照样能上传、能下载、能打包，只是不能删、不能改名
- 判定在服务端（路由层），不是前端置灰：被禁止的设备发请求会拿到 `403`，
  网页上那两个按钮也会置灰并挂一条黄条「电脑端已禁止这台设备删除 / 修改，上传下载不受影响」
- 电脑端自己（`X-TD-Secret`）**豁免**——否则关掉某台设备的授权后自己也删不动了
- 同一 IP 的多个标签页算**一台**设备，授权对它们一起生效；DHCP 换了 IP 会当成新设备
  （授权要重设，这是已知代价）
- 授权状态**不落盘**，重启后所有设备恢复"允许"

## 设置与在线更新

标题栏上的**齿轮**打开设置面板，有两块：

**关于**：应用名、当前版本、最新版本 + 检查更新 / 立即更新 / 立即重启。

**配对**：显示当前配对码、锁定状态，以及一个「重新生成配对码」按钮。

- 配对码输错次数过多会进入**冷却**（5 分钟，界面和手机页面都会显示还剩多少秒），
  冷却结束自动恢复——不会再出现「锁死了只能重启程序」的情况
- 万一被人恶意刷错码锁住，点「重新生成配对码」立刻换一张新码并解除锁定；
  已经配对的设备不受影响，新设备要用新码

其余：

- **月亮/太阳**按钮在标题栏上，点了立刻切浅色/深色，选择记在 `settings.json` 里
- 程序**完全不做主动检测**：只有你点「检查更新」时才会去问一次更新服务器。
  传输、网页、证书全在本地，不依赖任何外部服务，平时启动零联网
- 查到新版本后 → 点「立即更新」：下载新 exe → 校验 sha256 → 换掉正在运行的
  自己 → 「立即重启」生效。替换失败不会把程序弄丢（旧文件会自动换回去）；
  上一次留下的 `transdata.exe.old` 会在下次启动时自动清掉
- 更新源写在 exe 同目录的 `settings.json`：

```json
{
  "theme": "light",
  "update_url": "https://api.github.com/repos/hq20211124/transdata/releases/latest"
}
```

  默认查 GitHub Release（取 `tag_name` 当版本号、找 `.exe` 附件当下载地址）。
  也可以指向自己的服务器，返回这个 JSON 即可：

```json
{ "version": "1.2.0", "url": "https://…/transdata-1.2.0.exe",
  "sha256": "…（可选，填了就强制校验）", "notes": "更新说明（可选）" }
```

**更新链路的几条硬规矩**（都是「宁可更新失败，也不装错东西」）：

| 规矩 | 原因 |
|---|---|
| 更新源必须是 `https://` | 明文 http 下，清单和 exe 可以被一起换掉，清单里的 sha256 会和攻击者的文件「完全匹配」，校验等于没做 |
| Release 里只认 `.exe` 附件 | 以前找不到 exe 会退而求其次拿第一个附件，一个 `.sha256` 或 `.zip` 被当成程序装上，`transdata.exe` 当场报废 |
| 下载完必须能通过 sha256（清单给了的话） | 给了就必须对上；**没给**会在设置面板里黄字提示「无法校验完整性」，仍然允许继续 |
| 下载完还要看是不是 `MZ` 头 | 兜底：就算哈希对上了，一个 zip 装上去也是废的 |

## 从源码构建

需要 Rust（rustup），前端纯逻辑测试还需要 Node（只用内置 test runner，无第三方依赖）：

```powershell
cd transdata-rs
cargo test                                  # 后端单测（82 个）
node --test web/test/logic.test.js          # 前端纯逻辑单测（12 个）
cargo build --release
# 产物：target\release\transdata.exe（单文件，双击即用）
```

- 后端覆盖：子目录上传 / 断线清理 / 临时文件原子发布 / 校验 / zip 流式打包 /
  配对与鉴权 / 跨站拒绝 / 危险路径 / 配额 / 在线更新 / 重命名 / 截图落盘 / 单实例锁 /
  窗口按钮 / 目录树与折叠 / 按设备授权（403 与豁免）/ 传输不受授权影响 / 断开设备
- 前端覆盖：分批 / 去重 / 按引用删项 / 目录树 / 展开折叠 / 路径编码 / 截图命名
  —— `web/logic.js` 是纯函数，编译期被 `src/web.rs` 拼进 `/app.js` 一起下发，
  所以成品体积和请求数都不变，但逻辑可以在 node 里直接测

版本号在 `Cargo.toml` 里（当前 1.3.0），窗口标题栏和设置面板里显示的就是它。

## 安全模型

这是一个跑在局域网里的工具，威胁模型是「同一个 Wi-Fi 下的其他设备 / 其他网站 /
抓包者」，不是互联网上的匿名攻击者。

**已经做到的**

| 项 | 做法 |
|---|---|
| 设备授权 | 每台设备一个「删除 / 修改」开关；被禁止的设备发 `DELETE` / `POST /rename` 会拿到 403（判定在服务端，前端置灰只是提示）；上传下载不受影响 |
| 访问控制 | 设备必须先配对（扫码或 8 位配对码）才能访问任何文件；配对码每次启动重新生成，8 位数字 + 每设备限速（5 分钟 10 次）+ 30 次失败进入 5 分钟冷却，暴力破解不可行。冷却到点自动解除，设置面板还能一键换码立刻恢复 |
| 更新链路 | 只认 `https://`、只认 `.exe`、清单给了 sha256 就强制校验，再加 `MZ` 头兜底；细节见上文「更新链路的几条硬规矩」 |
| 传输加密 | 可选 HTTPS（自签证书，持久化；本机地址没变时手机只提示一次），见下文 |
| 凭据存放 | 会话凭证只有 `HttpOnly; SameSite=Strict` 的 Cookie，JS 读不到，跨站请求也不带。**唯一的例外是下载链接**：它带一个服务端签名的 `?e=&d=`（只授权「读这一个路径」，12 小时过期，不能列表 / 上传 / 删除）。因为 Via、X 浏览器这类会把下载交给系统下载器——那是另一条不带 Cookie 的连接，只认 Cookie 的话 200 KB 的文档也会报「网络连接失败」 |
| 常量时间比较 | 配对码 / 密钥比较用 `ct_eq`，不因比较耗时泄露信息 |
| 跨站防护 | 写操作校验 `Origin`；服务端不返回任何 CORS 头，别的网站读不到任何响应 |
| 路径穿越 | `..`、绝对路径、盘符、UNC、Windows 保留名（`CON`/`NUL`/`COM1`…）、非法字符 `<>:"|?*`、尾随点/空格全部拒绝；符号链接 / junction 不能跳出传输目录 |
| 磁盘打满 | 启动时按磁盘剩余空间算配额（至少留 1 GB），超了直接 507 停止；并发上传数上限 8 |
| 内存打爆 | 便签单次请求上限 4 MB；上传流式落盘，内存恒定 |
| XSS 纵深防御 | 严格 CSP（`script-src 'self'`、`style-src 'self'`，无内联脚本/样式），页面所有用户数据用 `textContent` 写入，附带 `nosniff` / `X-Frame-Options: DENY` / `Referrer-Policy: no-referrer` 等响应头 |
| 临时文件 | 打包**不落任何临时文件**：zip 边压边传直接写 socket，传输目录里不会出现半成品压缩包 |

**已知边界（诚实说明）**

- **默认不加密**：不打开 HTTPS 开关时，局域网内是明文 HTTP。同一 Wi-Fi 上有能力做
  ARP 欺骗 / 中间人的攻击者可以读到传输内容。**做敏感传输请打开 HTTPS 开关**
  （见下文「HTTPS」）。
- **配对后即长期有效**（12 小时无操作失效，或重启程序失效）。要提前踢掉某台设备，
  用设备表里的「断开」；「重新生成配对码」只影响**还没配对**的设备，已配对设备的
  会话不受影响。
- 传输目录里的文件对**已配对的设备**是等同本机文件对待的（默认可下载、可删除；
  删除 / 改名受上面的授权开关控制），这是工具的用途本身。
- **下载链接是一条 12 小时有效的读凭证**：拿到某个文件的链接（含签名）就等于能在
  过期前下载它，仅此一个文件，不能列目录、不能改名删除、不能上传。链接只由已配对
  的设备从 `/files` 取得；换配对码不影响已发出的链接，重启程序才作废。

## HTTPS（可选，默认关闭）

窗口里「访问地址」卡片下面有一个 **启用 HTTPS（加密传输）** 开关，勾上立刻生效
（端口不变，协议切换；地址和二维码自动跟着变）。

### 证书是怎么回事

公网 CA 不可能给 `192.168.x.x` 这种内网地址签发证书，所以程序**自己签一张**：

| 问题 | 答案 |
|---|---|
| 证书从哪来 | 首次启动时用程序内置的密钥生成（`rcgen`），签给本机所有 IPv4 地址 + `localhost` |
| 存在哪 | 程序目录下的 `transdata-tls-cert.pem` / `transdata-tls-key.pem`；目录不可写时落到 `%LOCALAPPDATA%\TransData\` |
| 会不会每次都变 | **不会**。证书和私钥都存在磁盘上，重启复用。只有当本机 IP 变了才会重新签发——而且不用等重启：程序每 3 秒核对一次本机地址，地址一变就重签并让端口用上新证书 |
| 私钥安全吗 | 私钥只在本机，文件权限跟目录继承；程序不会把它发出去 |
| 有效期 | 到 2035 年 1 月 1 日 |

**为什么要存到磁盘**：浏览器会记住「这个证书是例外」。证书不变 → 手机上只提示**一次**，
下次直接进页面。证书每次变 → 每次都要重新点一遍「继续前往」。反过来，如果地址变了不重签，
手机拿到的是「名字对不上」的证书，浏览器不给「继续前往」的按钮，页面直接打不开。
所以本机地址变化（换热点、DHCP 重新分配）后证书会重签一次，这时手机上要再接受一次警告。

### 客户（手机端）会看到什么

第一次用 `https://` 打开会提示证书不受信任，这是自签证书的正常现象：

- **Chrome / Edge（安卓）**：点「高级」→「继续前往（不安全）」
- **Safari（iPhone）**：点「显示详细信息」→「访问此网站」→「访问网站」
- 之后不再提示（证书没变）

想确认连的是不是这个程序：窗口里显示的 **SHA-256 证书指纹**，和手机证书详情里
显示的指纹应当一致。

### 用 http 打开了一个 https 端口

不会报一堆看不懂的网络错误，而是给一个页面，直接告诉你该用哪个地址。

### 注意事项

- 开了 HTTPS 之后，`http://` 的地址不能用了（端口只说一种话）
- 配对码、文件名、传输内容全部在 TLS 里，看不到也改不了
- 开了 HTTPS 之后新配对的设备会拿到带 `Secure` 标记的 Cookie
- 切换协议要重新配对：`Secure` Cookie 不会在 `http` 上发送，反过来也一样
- 「启用 HTTPS」但证书不可用（目录写不进去）时，端口仍在说 `http`，
  连接卡片会用红字写明——二维码给的也是实际生效的那个协议

## 传输速度排查

如果传输明显慢（如只有 2~3 MB/s），依次检查（均为网络环境问题，非程序缺陷）：

1. 两台电脑网卡链路速率：`ipconfig /all` 看「连接速度」是否 1 Gbps（100M 网卡上限 ~12MB/s）
2. 企业杀软/EDR 是否对读写做了实时扫描，把传输目录加入白名单
3. 尽量用有线；Wi-Fi 2.4GHz 或信号弱会显著掉速
4. `ping` 两台机器，延迟 >10ms 说明中间网络设备多，属正常损耗
